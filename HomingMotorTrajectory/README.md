# HomingMotorTrajectory

`Trajectory::HomingMotorTrajectory` 在 [MotorTrajectory](../MotorTrajectory/README.md) 的本地 S 曲线轨迹上增加堵转寻零：逐台寻找机械止挡、重置电机反馈角度，然后规划到归零后的逻辑目标。它依赖真实电机反馈和速度控制器输出判断堵转，不是限位开关或 GPIO 输入驱动。

入口为 [`homing_motor_trajectory.hpp`](homing_motor_trajectory.hpp) 中的 `trajectory::HomingMotorTrajectory<MotorNum>`。参数的已有 Doxygen 见该头文件，基础调度与曲线失败契约见 [MotorTrajectory README](../MotorTrajectory/README.md)；[根 README](../README.md) 提供仓库导航。

## 依赖与非拥有资源

[cpkg.toml](cpkg.toml) 声明包名 `Trajectory::HomingMotorTrajectory`，直接依赖：

- `MotorDrivers::Controller`：电机速度控制器、反馈角度及速度环输出。
- `Trajectory::MotorTrajectory`：基础轨迹规划、位置补偿及速度环周期入口；曲线相关依赖由该包传递引入。
- `stm32cubemx`：宿主生成的 `main.h` 与 HAL1 环境，归零计时实际调用 `HAL_GetTick()`。

构造时传入一个基础 `MotorTrajectory<MotorNum>` 的右值及归零配置，电机数量必须大于零。移动基础轨迹不会转移或创建底层电机、控制器的所有权；这些资源仍由宿主持有，并必须在归零和后续运行期间持续有效。不要继续使用被移出的基础轨迹驱动同一组控制器，也不要让其他任务同时改变其参考、输出上限或角度基准。

## 硬件输入与配置责任

宿主负责通过 CubeMX 完成可配置的通信外设、时钟、HAL 时基等静态配置，并保证电机反馈已正常刷新。`HAL_GetTick()` 必须按 HAL 毫秒时基持续推进；归零使用它判定堵转持续时间，不能以 `profileUpdate(dt)` 代替该硬件相关时间来源。

库在运行期设置寻点速度、临时限制速度环输出、执行控制更新并重置电机反馈角度，不初始化或修复宿主静态硬件配置。当前实现没有完整硬件配置校验，也不会验证机械止挡安全性或反馈链路有效性；不得把接入要求描述成库已经自动检查的条件。若需要补充校验、无法在库内校验，或遇到 HAL1 能力不足，先通过 Ask 确认处理方案，不增加寄存器或其他绕过路径。

归零参数中的 `speed` 与速度控制器参考单位一致；`max_current` 用于限制速度环输出，不等同于直接测量的物理电流。`min_ticks` 使用 ms，`dead_angle`、`offset` 和目标位置使用 deg。宿主应依据实际机械方向、止挡承载能力和驱动约束选择这些参数；包不提供适用于任意机构的安全参数保证。

## 调用顺序

1. 准备反馈有效的电机及速度控制器，构造基础轨迹，再移动构造归零轨迹并给定归零参数。
2. 调用 `startCalibration()`，使用配置中的归零后逻辑目标；也可显式传入本次归零后的逻辑目标。该操作会停止并禁用基础轨迹的正常控制路径，再逐台设置寻点速度、输出上限并尝试使能控制器。
3. 寻零期间持续调用归零对象的 `controllerUpdate()`，同时维持反馈刷新。此阶段由它执行寻点控制和归零状态推进，不能仅调用基础类速度环入口替代。
4. 全部电机完成堵转检测后，库恢复各自原有输出上限、重新使能基础轨迹，并规划归零后的逻辑目标。为完成这段移动，仍须周期调用 `profileUpdate(dt)`、`errorUpdate()`、`controllerUpdate()`；`dt` 使用秒。宿主可在整个归零流程中维持这三个周期入口，基础轨迹在寻点阶段处于禁用状态。
5. 等待 `isCalibrated()` 为真后再进入正常目标控制。它表示寻零及归零后的定位均已完成，不只是检测到了止挡。

堵转位置被重置为反馈角度零点；归零包的绝对目标入口将逻辑目标加上 `offset` 后交给基础轨迹。继承的反馈读数仍是基础电机坐标，相对目标入口也未提供统一的逻辑零位转换封装，不应假设所有继承接口都自动应用偏移。

## 失败与安全边界

- 堵转依据速度环输出接近所设上限且角度在指定时间内基本不变来判定，不是独立电流传感或限位输入的确认。反馈冻结、输出异常或机械条件不符可能影响归零判断，宿主必须负责相应保护。
- 寻点阶段没有内建超时或独立错误状态；`startCalibration()` 不返回每台控制器的使能结果。无法到达止挡时不能假定流程会自动报错或停机。
- 转入归零后定位时，基础使能或曲线规划失败会使流程继续停留在寻点状态，后续周期可能再次尝试；没有单独的归零失败返回接口。曲线失败信息仍遵循基础包契约，宿主不能只等待完成标志而不监控执行情况。
- `enabled()` 结合基础使能和归零完成状态，但继承接口并非全部以该派生状态为门禁。归零期间应由宿主限制外部目标命令，不能把状态查询当成全接口安全互锁。
- 完成判断沿用基础包的曲线时间和平均位置误差，不保证每台电机分别满足误差阈值。本包没有专用的归零取消/故障恢复接口；基础停止或禁用也不能被描述为自动退出归零状态机，宿主需管理后续调度与安全停机。
