# MotorTrajectory

`Trajectory::MotorTrajectory` 将位置轨迹转换为电机速度参考，并叠加每台电机的位置 PD 误差补偿。支持多个电机跟随同一位置目标，不是每台电机独立规划不同轨迹的接口。

- 本地规划入口：[`motor_trajectory.hpp`](motor_trajectory.hpp) 中的 `trajectory::MotorTrajectory<MotorNum>`，使用 S 曲线生成参考。
- 外部轨迹入口：[`motor_trajectory_slave.hpp`](motor_trajectory_slave.hpp) 中的 `trajectory::MotorTrajectorySlave`，消费调用方提供的位置、速度点，不在本包中重新规划或插值。

符号与参数的已有 Doxygen 见上述头文件；本文仅说明接入契约。仓库导航见[根 README](../README.md)，需要堵转归零时见 [HomingMotorTrajectory](../HomingMotorTrajectory/README.md)。

## 依赖与资源

[cpkg.toml](cpkg.toml) 声明包名 `Trajectory::MotorTrajectory`，直接依赖：

| 依赖 | 用途 |
| --- | --- |
| `MotorDrivers::Controller` | 外部速度控制器和电机反馈。 |
| `VelocityProfile::SCurve` | 本地 S 曲线规划及失败信息。 |
| `libs::PID_PD` | 各电机的位置误差补偿。 |
| `utils` | 中断临界区与外部轨迹点缓冲等基础设施。 |

通过宿主 cpkg 依赖接入，不手工修改生成的 CMake 文件。对象只保存传入控制器的非拥有指针；控制器及其关联电机必须非空且比轨迹对象活得更久。宿主负责反馈通信、更新节奏、资源访问协调与底层硬件配置。

目标位置和外部轨迹点的位置使用 deg，曲线速度和外部点速度使用 deg/s；传给速度控制器的参考转换为 rpm。多电机反馈应采用一致的逻辑坐标、方向与零位。`MotorTrajectory` 的电机数量应大于零；不能假定所有模板入口都已对此做编译期校验。

## 本地曲线接入顺序

1. 先准备电机及速度控制器，保证反馈有效，再构造轨迹对象并提供 S 曲线约束、位置 PD 参数及完成阈值。
2. 调用 `enable()` 并检查返回值。成功使能后先保持当前位置，再通过绝对或相对目标接口发起规划；未使能时目标设置返回 `false`。
3. 周期调用 `profileUpdate(dt)` 推进曲线，`dt` 使用秒且应反映实际调度间隔；调用 `errorUpdate()` 更新位置补偿，再调用 `controllerUpdate()` 执行速度环。宿主决定各入口的频率；同一轮更新时按此顺序使用新参考，避免对同一控制器重复执行速度环。
4. 持续刷新反馈并检查规划结果和完成状态；需要停止轨迹时调用 `stop()`，需要关闭控制器时调用 `disable()`。

衔接方式可以采用实际反馈状态或上一条曲线的当前参考状态。相对目标的基准也受该方式影响：沿上一曲线衔接时使用理论位置，否则使用实际平均位置，而不是无条件以旧目标终点为基准。

### 失败与完成边界

- 控制器使能失败会使全部关联控制器禁用并返回 `false`；调用方必须处理失败，不能仅以构造成功作为可运行依据。
- 曲线求解失败时目标设置返回 `false`，可用 `lastFailureInfo()` 查看曲线失败原因；原曲线不会被失败的新规划替换，不会因此自动停止。未使能导致的失败不代表产生了一条新的曲线失败信息。
- 完成条件结合曲线时间和**平均反馈位置**误差，不保证每台电机都已分别到位，也不表示具有独立失步或故障检测。
- `stop()` 停止曲线推进并以当前位置作为保持参考，不是急停或硬件断能；仍需周期控制才能保持。安全停机由宿主负责。

## 外部轨迹点接入顺序与边界

1. 选择缓冲模式或直接传点模式，先完成控制器构造和使能。缓冲模式要求 `MotorNum > 0`、`BufferCapacity >= 2`；直接传点模式使用 `Offline = true`，同样要求正的电机数量。
2. 缓冲模式通过 `pushTrajectoryPoint()` 提供点，每次 `profileUpdate()` 至多消费一个点。入队失败返回 `false`，宿主应处理容量不足。`profileUpdate(dt)` 不按 `dt` 插值或调节消费速度，调用次数决定消费节奏。
3. 直接传点模式由 `profileUpdate(point)` 应用当前点。随后与缓冲模式一样，周期执行误差补偿和速度环更新。

缓冲用尽后保持最后一个点的位置和速度，不自动将速度置零。`stop()` 清空缓冲并将目标改为当前位置、零速度；`clearTrajectory()` 只清空待消费点，不撤销当前目标。使能成功也会执行停止操作，因此应在使能后再入队。

缓冲模式的周期入口受使能和 `lock()` 状态约束，但锁定不清空队列、不禁用电机。直接传点的 `profileUpdate(point)` 当前不检查使能或锁定状态，调用方必须自行限制何时送点；不得把 `lock()` 当作所有模式统一的安全互锁。
